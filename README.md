# ProfHunter

Flutter-приложение с PocketBase. Структура БД хранится в
`pb_migrations/1793448000_profhunter.js` (PocketBase 0.23+).

## Развёртывание схемы

Миграция рассчитана на новую БД с пустой стандартной auth-коллекцией
`users`. Она создаёт все поля пользователей и пять прикладных коллекций.
Для существующей рабочей БД сначала экспортируйте схему и сделайте резервную
копию: миграция намеренно останавливается при наличии прикладных коллекций.
Не удаляйте существующие коллекции ради запуска миграции.

Скопируйте `pb_migrations` рядом с исполняемым файлом PocketBase, затем выполните:

```sh
./pocketbase migrate up
./pocketbase serve --http=127.0.0.1:8090
```

На хостинге включите папку миграций в образ/деплой и храните `pb_data` на
постоянном диске. Автоматический откат отключён, поскольку удаление коллекций
уничтожило бы данные. Для отката восстановите резервную копию БД и файлов.

## Коллекции и связи

| Коллекция | Поля | Связи |
| --- | --- | --- |
| users (auth) | email/password (системные), name, companyName, selectedRegion, role, avatar, resume, aboutMyself, aboutCompany, skills | role: candidate/company |
| vacancy | name, salary, companyName, employmentType, place, address, duties, requirements, conditions, contacts | userID → users |
| response | — | idVacancy → vacancy, idCandidate → users |
| favorite | — | user → users, vacancy → vacancy |
| chat | lastMessage | idCompany → users, idVacancy → vacancy, idCandidate → users |
| message | textMessage, isRead | chatId → chat, senderId → users |

Все коллекции имеют id, created и updated. Списки skills, duties, requirements,
conditions и объект contacts хранятся как JSON. avatar и resume — файловые поля.
Уникальные индексы запрещают повторный отклик и избранное для одной пары,
а также повторный чат кандидата по вакансии. При удалении связанной записи
зависимые записи удаляются каскадно.

Авторизованные пользователи читают профили и вакансии. Профиль редактирует
владелец; изменение роли через API запрещено. Вакансии создают компании и
редактируют их владельцы. Отклики видят кандидат и владелец вакансии,
избранное — его владелец, чаты и сообщения — участники. Читатель сообщения
может изменять isRead. Email по умолчанию скрыт стандартными настройками
PocketBase; публичные контакты вакансии задаются отдельно. Аватары и резюме
не защищены файловым токеном: приложение использует обычные URL файлов.

Dart-модели и GetX-зависимости остаются в приложении: они нужны для
десериализации и создания сервисов, в БД переносится структура хранения
и связи между записями.

## Подключение приложения

```sh
flutter pub get
flutter run --dart-define=POCKETBASE_URL=http://127.0.0.1:8090
```

Для Android Emulator используйте `http://10.0.2.2:8090`, для устройства —
доступный ему адрес сервера. По умолчанию используется `http://185.239.50.152`.
Используйте HTTPS для размещённого сервера.

## Проверка после применения

На тестовой БД зарегистрируйте company и candidate. От компании создайте
вакансию; от кандидата добавьте избранное, отклик и чат, отправьте сообщение.
Проверьте `expand: vacancy` и `expand: idVacancy,idCandidate`, доставку
сообщений и запрет доступа к чужому чату/избранному. Повторные пары должны
отклоняться БД. Не проверяйте каскадное удаление на рабочих данных.

коллекций, поля, relation-связи, правила доступа и индексы. Записи не создавались;
сценарии приложения с авторизацией и файлами пока не проверены.

JS-миграция предназначена для новой БД. На этом сервере повторно запускать её
не нужно: схема уже создана через импорт, а файл отсутствует в истории
серверных миграций.
